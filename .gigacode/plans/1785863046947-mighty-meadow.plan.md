# Fix: Hash mismatch in Telegram Auth verification

## Root Cause

В методе `TelegramAuthController.verifyTelegramAuth()` значения параметров **не декодируются** из URL-encoding перед построением `dataCheckString`, хотя по документации Telegram их **нужно декодировать**.

Согласно [Telegram docs](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app):
> Before that, **URL-decode the values of all parameters** (but not the keys!).

В коде сейчас:
```java
params.put(kv[0], kv[1]); // Generally don't decode!  ← ОШИБКА
```

Из-за этого при вычислении HMAC-SHA256 для `dataCheckString` используются закодированные значения (например, `%7B%22id%22...` вместо `{"id"...}`), что даёт неверный хэш.

## План исправления

### Файл: `src/main/java/com/github/barbershop/account/controller/TelegramAuthController.java`

**Метод `verifyTelegramAuth`** — добавить URL-decode значений:

```java
params.put(kv[0], URLDecoder.decode(kv[1], StandardCharsets.UTF_8));
```

Также закомментировать/убрать отладочный `System.out.println` и включить реальную проверку (`valid = verifyTelegramAuth(...)`).

### Файл: `src/main/java/com/github/barbershop/account/service/TelegramAuthValidator.java`

Реализовать методы `validate()` и `extractUserData()` в сервисе (заменить логику из контроллера).

### Файл: `src/main/java/com/github/barbershop/account/controller/TestHash.java`

Можно удалить — это тестовый файл.

### Тесты

- `TelegramAuthValidatorTest` — должен заработать после реализации метода `validate()` в `TelegramAuthValidator`

## Верификация

1. Запустить `mvnw test` — тест `TelegramAuthValidatorTest` должен пройти
2. Удалить `TestHash.java`
3. Проверить, что `verifyTelegramAuth` правильно сравнивает хэши для реальных initData из Telegram
